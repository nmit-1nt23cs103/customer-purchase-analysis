# Customer Purchase Analysis

Customer segmentation and campaign-response prediction on the Kaggle
[Customer Personality Analysis](https://www.kaggle.com/datasets/imakash3011/customer-personality-analysis)
dataset (about 2,200 customers with purchase history across wine, meat, fish, fruit, sweets and gold products,
plus web, catalog and store channel activity and past campaign responses).

**Python · SQL (SQLite) · scikit-learn · pandas · matplotlib**

## What this project does

| Stage | What happens | Where |
|---|---|---|
| Preprocessing | Parse dates, fix data-entry oddities, remove duplicates and outliers, impute missing income, engineer features (age, tenure, total spend, family size, ...) | `src/preprocess.py` |
| SQL | Cleaned data is loaded into SQLite; features are extracted with SQL and 13 reporting queries (joins, CTEs, window functions, CASE bucketing) produce business metrics | `sql/`, `src/sql_analysis.py` |
| Clustering | K-Means on spend and demographics; k chosen with elbow and silhouette; stability and algorithm cross-checks; segment profiling | `src/segmentation.py` |
| Classification | Predict who will accept the next campaign (Logistic Regression, Random Forest, Gradient Boosting) with cross-validation, threshold tuning and permutation importance | `src/classification.py` |
| Visualisation | Distributions, spend trends, segment maps and profiles, ROC / PR curves, feature importance | `reports/figures/` |

## Quick start

```bash
git clone <your-repo-url>
cd customer-purchase-analysis
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 1. Get the data (needs a free Kaggle account / API token), or place marketing_campaign.csv in data/raw/ by hand
python -m src.download_data

# 2. Run everything: clean -> EDA -> segments -> SQL -> classifier -> reports
python -m src.run_pipeline

# Optional
python -m src.segmentation --k 4      # force a specific number of segments
python -m pytest                      # unit tests (run on synthetic data)
```

Individual steps can be run on their own (`python -m src.preprocess`, `python -m src.sql_analysis`, ...),
but they depend on the outputs of the earlier steps.

## Method notes

- **Cleaning.** Duplicate customers (identical apart from ID), impossible birth years (age over 100) and extreme
  incomes (above Q3 + 3xIQR) are removed. Missing income is filled with the median of the customer's education
  group. The constant columns `Z_CostContact` and `Z_Revenue` are dropped. Age and tenure are measured at the
  dataset's snapshot date (the day after the last signup), not today's date.
- **Segmentation.** Skewed spend features are log-transformed and all features standardised before K-Means.
  k is picked by silhouette score from 3-6 clusters; segments are numbered by average spend (Segment 0 =
  highest). Names such as "Premium, parents" are generated from the segment profile; rename them after
  reviewing the profile heatmap.
- **Classification.** Only about one customer in seven responds to the campaign, so accuracy is misleading.
  Models use class weights and are compared on PR-AUC and ROC-AUC. The decision threshold is tuned on
  cross-validated predictions from the training set only; the test set is used once for the final numbers.
- **Known limitation.** The segment label is a feature of the classifier. It is learned from unlabelled
  behavioural features (not from the response), but it is fitted on the full dataset before the train/test
  split. For a production system, fit the clustering inside the training fold.
